# file_parser

file_parser — Python-библиотека для извлечения структурированных данных из неоднородных Excel- и CSV-документов.

Проект решает типичную задачу обработки «грязных» табличных файлов: заголовки могут находиться не в первой строке, таблицы — быть смещенными, данные — содержать лишние символы, объединенные ячейки, разные форматы цен и единиц измерения. Парсер определяет табличные области, находит заголовки, сопоставляет колонки с ожидаемыми полями, нормализует значения и возвращает результат в виде JSON-совместимой структуры.

### Возможности
- Поддержка .xlsx, .xlsm, .xls, .csv и .tsv; 
- Обработка всех листов Excel-файла; 
- Поиск нескольких табличных областей на одном листе; 
- Fuzzy-сопоставление заголовков с целевыми полями; 
- Fallback-парсинг, если основной метод не смог извлечь данные; 
- Нормализация цен, количества и единиц измерения; 
- Очистка SKU и защита от спутывания цены с артикулом; 
- Фильтрация пустых и мусорных строк; 
- Оценка уверенности извлечения (confidence); 
- Флаг needs_ai для передачи сложных файлов в AI-обработку; 
- Сохранение результата в JSON; 

### Как это работает
Пайплайн обработки файла:

```
Файл
  → определение формата
  → чтение Excel/CSV
  → поиск табличных областей
  → поиск строки заголовков
  → fuzzy-сопоставление колонок
  → извлечение и нормализация строк
  → оценка качества
  → fallback при необходимости
  → ParseResult
```

Для Excel-файлов основным подходом является pandas + fuzzy-поиск заголовков. Если он не дает результата, используются fallback-парсеры:

- ```.xlsx``` — ```openpyxl```;
- ```.xls``` — ```xlrd```;
- ```.csv``` / ```.tsv``` — ```pandas``` с перебором разделителей.

Для CSV поддерживаются разделители ```;```, ```,```, ```\t``` и ```|```.

### Поддерживаемые поля
Парсер пытается найти и нормализовать следующие поля:

| Поле         | Описание             |
| ------------ | -------------------- |
| name         | Наименование позиции |
| sku          | Артикул / код товара |
| unit         | Единица измерения    |
| quantity     | Количество           |
| price        | Цена                 |
| manufacturer | Производитель        |
| notes        | Примечание           |

Итоговая запись выглядит так:
```
json
{
  "name": "Кабель USB-C 1м",
  "sku": "USB-C-001",
  "unit": "шт",
  "quantity": "10",
  "price": 590.0,
  "manufacturer": "Example",
  "notes": ""
}
```

### Результат парсинга
Метод parse_file() возвращает объект ParseResult.

```
python
from file_parser import ExcelParser

parser = ExcelParser()
result = parser.parse_file("examples/invoice.xlsx")

print(result.items)
print(result.confidence)
print(result.needs_ai)
print(result.method)
print(result.errors)
```

Пример структуры результата:

```
json
{
  "file_path": "examples/invoice.xlsx",
  "file_hash": "sha256-hash",
  "items": [
    {
      "name": "Кабель USB-C 1м",
      "sku": "USB-C-001",
      "unit": "шт",
      "quantity": "10",

    "name": 0,

  }

```

### Оценка качества
После извлечения данных рассчитывается ```confidence``` — численная оценка качества результата.

Если ```confidence``` ниже порога 0.55 или позиции не найдены, устанавливается:

```
python
result.needs_ai = True
```

Это позволяет строить двухэтапную обработку:

1. Сначала файл обрабатывается детерминированными правилами.
2. Если результат недостаточно надежный, документ передается в OCR / LLM / Document AI-пайплайн.

Такой подход снижает стоимость и количество ошибок по сравнению с отправкой всех документов в LLM.

## Быстрый старт

```
python
from pathlib import Path

from file_parser import ExcelParser

parser = ExcelParser()
result = parser.parse_file("data/prices.csv")

if result.items:
    print(f"Найдено позиций: {len(result.items)}")
    print(f"Метод: {result.method}")
    print(f"Уверенность: {result.confidence:.2f}")
else:
    print("Данные не извлечены")
    print(result.errors)

output = Path("output/result.json")
result.write_parse_result_to_json(output)
```

## Архитектура
```ExcelParser```

Основной класс библиотеки.

- ```parse_file()``` — публичная точка входа;
- ```_parse_spreadsheet()``` — маршрутизация по типу файла;
- ```_parse_dataframe_with_fuzzy()``` — основной fuzzy-парсинг;
- ```_standard_xlsx_fallback()``` — fallback для ```.xlsx```;
- ```_standard_xls_fallback()``` — fallback для ```.xls```;
- ```_standard_csv_fallback()``` — fallback для CSV/TSV;
- ```_build_item()``` — сборка и валидация одной позиции.

```ParseResult```

Дата-класс с результатом обработки:

- ```file_path``` — путь к исходному файлу;
- ```file_hash``` — хеш файла;
- ```items``` — список извлеченных позиций;
- ```confidence``` — оценка качества;
- ```needs_ai``` — флаг необходимости AI-обработки;
- ```errors``` — список ошибок;
- ```method``` — использованный метод парсинга;
- ```col_map``` — сопоставление колонок.

## Обработка сложных файлов

Парсер рассчитан на файлы, где:

- заголовок находится не в первой строке;
- на листе несколько таблиц;
- колонки имеют разные названия;
- числа записаны с пробелами, запятыми или нестандартными разделителями;
- присутствуют пустые строки, служебные строки и объединенные области;
- цена может быть перепутана с артикулом.

Если основной fuzzy-подход не смог надежно распознать структуру, включается fallback. Если и он не дает приемлемого качества, результат помечается как needs_ai=True.

## Ограничения

- PDF, DOC и DOCX пока не поддерживаются;
- OCR для сканов и изображений не реализован;
- LLM-обработка не встроена: библиотека только определяет необходимость такого шага через needs_ai;
- Качество fuzzy-распознавания зависит от языка и формата заголовков;
- Для сильно нестандартных сканов может потребоваться OCR + layout analysis.
